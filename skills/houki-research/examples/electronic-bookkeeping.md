# Example — 領収書を PDF で保存する機能は、法令のどこに触れるか

[`workflows/feasibility-check.md`](../workflows/feasibility-check.md) を、実際の問いに当てた記録。MCP の応答は **2026-09-19 05:05〜05:06 UTC（14:05〜14:06 JST）に houki-egov-mcp v0.6.1 / houki-nta-mcp v0.18.1 の dev サーバーで実測**したもので、引用はそのまま写している。

## 問い

> 経費精算のアプリに、取引先からメールで届いた領収書の PDF をそのまま保存する機能を作ります。紙で受け取った領収書はスキャンせず、当面は電子で届いたものだけが対象です。法令上の要件を教えてください。

問いの形は「この仕様は法令のどこに触れるか」。自社のアプリの仕様を確かめる自己の事務なので、業法の線に近づかない。「適法か」とは聞かれていないが、回答でも可否は書かない。

## Skill の動作

### ① 業法判定

自己の事務。そのまま進める。

### ② 仕様の語を法令の語に置き換える

| 仕様の語 | 置き換えた法令の語 | 根拠 |
|---|---|---|
| メールで届いた領収書の PDF | 電子取引の取引情報に係る電磁的記録 | 電帳法 2 条 5 号の定義に「領収書」が明記されている（後掲） |
| 保存する | 保存、保存すべきこととなる期間・場所 | 施行規則 4 条 1 項の語 |
| 紙の領収書はスキャンしない | （対象外）スキャナ保存 | 電帳法 4 条 3 項の領域。今回は探さない |

略称「電帳法」は `resolve_abbreviation` で正式名に直した（下記 ③）。

**探した語**: 電子取引 / 電磁的記録 / 保存 / 電帳法。
**探さなかった語**: スキャナ保存（仕様の対象外）、個人情報（領収書に個人名が入る場合は別の調査になる。未確認に回す）。

### ③ 該当法令を探す

```jsonc
// houki-egov-mcp
{ "tool": "resolve_abbreviation", "args": { "abbr": "電帳法" } }
// → formal: "電子計算機を使用して作成する国税関係帳簿書類の保存方法等の特例に関する法律", source_mcp_hint: "houki-egov"

{ "tool": "search_fulltext", "args": { "keyword": "電子取引 電磁的記録 保存", "limit": 8 } }
// → source: "bulk", 8 件。freshness.staleness: "stale"（last_sync 2026-09-07、12 日前）
```

`search_fulltext` の 8 件の内訳:

| 法令 | 条 | 見出し | 今回の仕様に |
|---|---|---|---|
| 電帳法（平成十年法律第二十五号） | 7 | 電子取引の取引情報に係る電磁的記録の保存 | **該当** |
| 電帳法施行規則（平成十年大蔵省令第四十三号） | 4 | 同上 | **該当**（委任先が同時に見つかった） |
| 関税法 | 94の5 / 7の9 | 電子取引の取引情報に係る電磁的記録の保存 ほか | 対象外。輸入取引の帳簿の話で、経費精算のアプリには関係しない |
| 関税法施行規則 | 9の10 / 10の3 / 8 / 11 | 同上 | 対象外 |

ローカル DB があると、法律と施行規則の両方が 1 回の検索で当たる。関税法が混ざるのは語が同じためで、**除外した理由を回答に書く**。

### ④ 条文を取る

```jsonc
{ "tool": "get_law", "args": { "law_name": "電帳法", "article": "7" } }
{ "tool": "get_law", "args": { "law_name": "電帳法", "article": "2", "item": 5 } }
```

電帳法 7 条（取得 2026-09-19T05:05:22Z）:

> 所得税（源泉徴収に係る所得税を除く。）及び法人税に係る保存義務者は、電子取引を行った場合には、財務省令で定めるところにより、当該電子取引の取引情報に係る電磁的記録を保存しなければならない。

電帳法 2 条 1 項 5 号（定義）:

> 五 電子取引　取引情報（取引に関して受領し、又は交付する注文書、契約書、送り状、**領収書**、見積書その他これらに準ずる書類に通常記載される事項をいう。以下同じ。）の授受を電磁的方式により行う取引をいう。

7 条に「財務省令で定めるところにより」とあるので、要件の実体は施行規則にある（⑤）。

### ⑤ 委任先へ下りる

③ で施行規則 4 条が見つかっているので、そのまま取る。見つかっていなければ `search_law { "keyword": "<法律名>", "law_type": "MinisterialOrdinance" }` で探す。

```jsonc
{ "tool": "get_law", "args": { "law_name": "電子計算機を使用して作成する国税関係帳簿書類の保存方法等の特例に関する法律施行規則", "article": "4" } }
```

施行規則 4 条 1 項（要点。全文は長いので、要件の骨だけ引く）:

> 法第七条に規定する保存義務者は、電子取引を行った場合には、当該電子取引の取引情報…に係る電磁的記録を、当該取引情報の受領が書面により行われたとした場合…に、国税に関する法律の規定により、当該書面を保存すべきこととなる場所に、当該書面を保存すべきこととなる期間、次に掲げる措置のいずれかを行い、第二条第二項第二号及び第六項第五号…に掲げる要件…に従って保存しなければならない。
> 一 当該電磁的記録の記録事項にタイムスタンプが付された後、当該取引情報の授受を行うこと。
> 二 …当該電磁的記録の記録事項にタイムスタンプを付すこと。（イ 授受後速やかに / ロ 業務の処理に係る通常の期間を経過した後速やかに。規程がある場合に限る）
> 三 次に掲げる要件のいずれかを満たす電子計算機処理システムを使用して…（イ 訂正又は削除の事実及び内容を確認できる / ロ 訂正又は削除ができない）
> 四 …正当な理由がない訂正及び削除の防止に関する事務処理の規程を定め、当該規程に沿った運用を行い…規程の備付けを行うこと。

**規則 4 条の中に、さらに規則 2 条 2 項 2 号と 6 項 5 号への準用がある**。これも取る。

```jsonc
{ "tool": "get_law", "args": { "law_name": "電子計算機を使用して作成する国税関係帳簿書類の保存方法等の特例に関する法律施行規則", "article": "2", "paragraph": 6, "item": 5 } }
```

施行規則 2 条 6 項 5 号（検索機能）:

> 五 当該国税関係書類に係る電磁的記録の記録事項の検索をすることができる機能（次に掲げる要件を満たすものに限る。）を確保しておくこと。
> - イ 取引年月日その他の日付、取引金額及び取引先…を検索の条件として設定することができること。
> - ロ 日付又は金額に係る記録項目については、その範囲を指定して条件を設定することができること。
> - ハ 二以上の任意の記録項目を組み合わせて条件を設定することができること。

規則 4 条 1 項の括弧書きに、この検索要件が **緩和される条件**（基準期間の売上高 5,000 万円以下、または日付・取引先ごとに整理した出力書面の提示に応じられる場合で、電磁的記録の提示等の要求に応じられるとき）が書いてある。緩和されるかどうかは事業者の規模と運用に依存するので、回答では「何が事実に依存するか」として列に残す。

「保存すべきこととなる期間」は電帳法側には書かれておらず、国税に関する法律（法人税法・所得税法）側にある。法人なら:

```jsonc
{ "tool": "get_law", "args": { "law_name": "法人税法施行規則", "article": "59", "paragraph": 1 } }
```

> 青色申告法人は、次に掲げる帳簿書類を整理し、起算日から七年間、これを納税地…に保存しなければならない。…三 取引に関して、相手方から受け取つた注文書、契約書、送り状、領収書、見積書…

規則 2 条 2 項 2 号（見読可能装置の備付け）は今回取っていない。**未確認**に回す。

### ⑤': 税に関わる仕様なので houki-nta-mcp も引く

```jsonc
// houki-nta-mcp
{ "tool": "nta_search_tax_answer", "args": { "keyword": "電子取引", "limit": 5 } }
// → 1 件: 5930「帳簿書類等の保存期間」(法人税)。legal_status.binds_tax_office: false

{ "tool": "nta_search_qa", "args": { "keyword": "電子取引", "limit": 5 } }
// → 0 件。hint: 「DB の質疑応答事例 1,841 件に「電子取引」に合う文書はありません」

{ "tool": "nta_get_tax_answer", "args": { "no": "5930", "format": "json" } }
// → source: "live"（初回取得。DB に書き戻し）
```

タックスアンサー 5930 の本文は、法人の帳簿書類の保存期間を「確定申告書の提出期限の翌日から 7 年間」（欠損金がある年度は 10 年）と書き、電子取引の保存については **「国税庁ホームページ『電子帳簿保存法 Q&A（一問一答）』を参照してください」** と案内している。つまり電帳法の Q&A は国税庁のこのページにあり、houki-nta-mcp の 6 種別には入っていない。回答では「対象外」と書いて URL を案内する。

### ⑥ 施行日と未施行の改正

```jsonc
{ "tool": "get_law_revisions", "args": { "law_name": "電帳法", "latest": 4 } }
```

| 施行日 | 改正法 | 状態 |
|---|---|---|
| **2027-01-01** | 令和七年法律第十三号（所得税法等の一部を改正する法律） | **UnEnforced**（公布済み・未施行） |
| 2025-04-01 | 令和七年法律第十三号 | CurrentEnforced（現行） |
| 2022-04-01 | 令和二年法律第八号 | PreviousEnforced |
| 2022-01-01 | 令和三年法律第十一号 | PreviousEnforced |

未施行の改正がある。アプリの稼働が 2027 年以降なら、その版で条文を確かめる必要がある。`get_law` の `at` で取れる:

```jsonc
{ "tool": "get_law", "args": { "law_name": "電帳法", "article": "7", "at": "2027-01-01" } }
// → 7 条の本文は現行と同一（応答に "時点: 2027-01-01" が付く）
```

7 条は 2027-01-01 の版でも変わらない。**どの条が変わるか**は本ワークフローの範囲外（`revision-tracking.md`、予定）なので、「7 条は変わらない。ほかの条の変更は未確認」と書く。施行規則側の未施行改正は今回見ていない。これも未確認。

## この例で分かった、手順書への反映

| 発見 | 手順書への反映 |
|---|---|
| ローカル DB があると、`search_fulltext` 1 回で法律と施行規則の両方に当たる | ⑤ に「③ で施行規則が同時に見つかっていればそのまま取る。無ければ `law_type` で探す」を足した |
| 施行規則 4 条の中に、規則 2 条への準用がある（二段目の委任） | ⑤ に「規則の条がさらに別の条を準用していたら、その条も取る」を足した |
| `get_law` の `at` で未施行版の条文が取れる | ⑥ に書いた。7 条の本文は変わらなかったが、どの条が変わるかは `revision-tracking.md` の領域 |
| 語が同じ別分野の法令（関税法）が混ざる | ② の「探した語」の記録に、除外した法令と理由も書くようにした |
| 電帳法 Q&A（一問一答）は houki-nta-mcp に無く、タックスアンサー 5930 自身が国税庁サイトへ案内している | ⑤' の記述どおり。変更なし |

## アンチパターン（この例で起きうるもの）

- ❌ 電帳法 7 条だけ引いて「電磁的記録を保存すればよい」と答える → タイムスタンプ・訂正削除の履歴・検索機能・7 年の保存期間が全部抜ける。要件は施行規則と法人税法側にある
- ❌ 規則 4 条の括弧書きを読まずに「検索機能は必須」と書く → 売上高 5,000 万円以下などで緩和される。事実に依存する条件として列に残す
- ❌ 「2027-01-01 に改正があるので今の条文は使えない」と書く → `at: "2027-01-01"` で取った 7 条の本文は同一。どの条が変わるかを見ずに断定しない
- ❌ 関税法のヒットを「関係する法令」に入れる → 語が同じだけ。除外の理由を書いて外す
- ❌ 「この設計なら電帳法に対応しています」と書く → 可否の判定。返さないもの
